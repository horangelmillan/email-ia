# ADR-004: Capa de BD — Drizzle + libSQL + migraciones + almacén seguro de claves

- **Estado**: Aceptado
- **Fecha**: 2026-08-20
- **Reemplaza a**: Ninguno (concreta ADR-002 §Persistencia y PROJECT_STATE Tarea 2)
- **Referencias**: ARCHITECTURE_DECISIONS.md §3.6 y §8 D6, ADR-002, PROJECT.md:41, ENGINEERING.md:39-49, PROJECT_STATE.md:134

## Contexto

La Fase 2 requiere materializar la capa de persistencia: SQLite cifrado, migraciones versionadas, esquema base `emails`/`contacts` y puerto de persistencia en el Core con claves en el almacén seguro del SO. El stack aprobado es `Drizzle + Drizzle Kit + SQLCipher`. En Windows el driver nativo `better-sqlite3` exige **Visual Studio Build Tools** ausentes en la máquina de desarrollo (fallo `gyp ERR! Could not find any Visual Studio installation`). Bloquea la instalación de la dependencia nativa y estabilizar el baseline.

## Decisión

- **ORM**: `drizzle-orm` (versión 0.45+) con dialecto `sqlite-core`.
- **Driver**: `@libsql/client` (libSQL, file + `:memory:`) vía `drizzle-orm/libsql`. Evita compilación nativa, expone `createClient({ url, encryptionKey })` compatible con cifrado en reposo; cuando se dispone de `better-sqlite3-multiple-ciphers` se sustituye el cliente sin cambiar el esquema (abstraído en `packages/db/src/client/connection.ts`). `DATABASE_URL` y `DATABASE_ENCRYPTION_KEY` configurables por env.
- **Migraciones**: `drizzle-kit` (SQLite, `drizzle/*.sql` + `meta/_journal.json`). Helper `migrate(db)` aplica los SQL con breakpoints en cualquier cliente (`libSQL` o `better-sqlite3`). Esquema base en `packages/db/src/schema/{contacts,emails}.ts`, exportado desde `packages/db/src/schema/index.ts`. Primera migración `0001_initial.sql` crea `contacts` (id/email único/display_name/timestamps) y `emails` (id/account_id/thread_id/from/to/subject/snippet/body/is_read/received_at/timestamps).
- **Puertos en Core**: nuevos puertos `ContactRepositoryPort` (`packages/core/src/ports/contact.port.ts`) y `EmailRepositoryPort` (`packages/core/src/ports/email.port.ts`) + `SecretStorePort` (`packages/core/src/ports/secret-store.port.ts`) y error unificado `DbError extends AppError` (`code DB_ERROR`). Exportados desde `@email-ia/core`.
- **Adaptadores en `packages/db`**: `DrizzleContactRepository` y `DrizzleEmailRepository` implementan los puertos del Core; `EnvSecretStore` (memoria + fallback `process.env` prefijado `SERVICE__ACCOUNT`) y `KeytarSecretStore` (delegación a `keytar` con fallback a `EnvSecretStore` vía `createSecretStore()` dinámico) implementan `SecretStorePort`. Conexión centralizada `createDb()`/`createInMemoryDb()` resuelve `url`/`encryptionKey` desde opciones, `DATABASE_URL`/`DATABASE_ENCRYPTION_KEY` o `SecretStorePort` (`email-ia/db-encryption-key` por defecto).
- **Config**: `drizzle.config.ts` en raíz y `packages/db/drizzle.config.ts` (schema `packages/db/src/schema`, out `packages/db/drizzle`, dialect `sqlite`).
- **Hexagonal**: `packages/core` no depende de `drizzle-orm`/`@libsql/client`; `packages/db` depende de `@email-ia/core` y adapta los puertos. Orden topológico: `core → db → backend`.

## Alternativas evaluadas

| Opción                                                             | Resultado                                                                                                                                                                                |
| ------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `better-sqlite3` + `drizzle-orm/better-sqlite3`                    | Descartada temporalmente: requiere VS Build Tools en Windows; se reintroduce como cliente alternativo cuando la toolchain nativa esté disponible (cambio solo en `client/connection.ts`) |
| `better-sqlite3-multiple-ciphers` (SQLCipher pragma `key`/`rekey`) | Compatible y deseable para producción; mantenida como evolución del cliente libSQL (API pragmas idéntica)                                                                                |
| `drizzle-orm/node-sqlite` (`node:sqlite`)                          | Requiere Node ≥22.5 y no expone `encryptionKey`; descartada por falta de cifrado uniforme                                                                                                |
| `Prisma` / `Kysely`                                                | Descartadas por decisión cerrada D6 (ADR-002)                                                                                                                                            |
| `shared` para puertos de persistencia                              | Descartado: `shared` es para utilidades sin semántica de dominio (ADR-003)                                                                                                               |

## Consecuencias

Positivas:

- Baseline verde sin toolchain nativa (cobertura >80 %, `pnpm build/typecheck/lint/format:check/test:coverage` OK).
- Esquema base versionado y portable; migración aplicable con `pnpm --filter @email-ia/db exec drizzle-kit` o helper `migrate()`.
- Claves nunca en código ni en `.env` commiteado; `SecretStorePort` permite `keytar`/`safeStorage` en Electron y `EnvSecretStore` en tests/CI.

Negativas / pendientes:

- Cifrado real en reposo pendiente de validar con binario SQLCipher/libSQL con clave (hoy verificado vía `encryptionKey` de libSQL y `EnvSecretStore`).
- `better-sqlite3-multiple-ciphers` y `keytar` se añaden a `allowBuilds` cuando se active la toolchain nativa.
- Índices/FTS/RAG vectorial y `account`/`thread` como entidades completas quedan para Fase 2+ (esquema base minimalista).
