# ADR-007: CI/CD completo — quality gate + dependabot + CodeQL

- **Estado**: Aceptado
- **Fecha**: 2026-08-26
- **Reemplaza a**: Ninguno (concreta ARCHITECTURE_DECISIONS §3.4 y §8 D9-D10, PROJECT_STATE Fase 3)
- **Referencias**: ARCHITECTURE_DECISIONS §3.4, §3.8, §4, §6 D9-D10, ADR-001, ADR-002, PROJECT_STATE Fase 3A, .github/workflows/ci.yml, .github/workflows/codeql.yml, .github/dependabot.yml

## Contexto

Fase 2 completada (ADR-006, baseline 72 tests 91.05 %/81.34 % verde). `PROJECT_STATE.md:142` define Fase 3 como CI/CD completo + observabilidad + contratos. El workflow `ci.yml` inicial cubría `lint/build/typecheck/test:coverage/gitleaks` pero omitía `format:check` (Prettier `eol=lf` + `.gitattributes`), `concurrency` cancel-in-progress, `timeout` y gate explícito de cobertura. `dependabot.yml` existía pero sin verificación de `Dependabot alerts/security updates`. `CodeQL` estaba pendiente de evaluación (ARCHITECTURE_DECISIONS §3.4: "evaluar si no añade mucha complejidad", impacto cuota Actions en plan Free).

## Decisión

- **CI `quality` endurecido** (`.github/workflows/ci.yml`): `concurrency: group ci-${{ github.ref }} cancel-in-progress:true`, `permissions: contents:read`, `timeout-minutes:15`, pasos en orden `lint → format:check → typecheck → build → test:coverage (threshold 80 % via vitest.config.ts:24..28) → gitleaks`. `format:check` previene recaída CRLF (`core.autocrlf false` + `.gitattributes:2`). Cobertura gate ya en `vitest` thresholds; step renombrado `Test with coverage (threshold 80%)` para visibilidad. Mantiene `pnpm@11.11.0` + `.nvmrc` Node 22 + `cache: pnpm` + `fetch-depth:0`.
- **Dependabot** (`.github/dependabot.yml`): mantiene `pnpm` + `github-actions` weekly `open-pull-requests-limit:10`. Alerts/security updates se activan en Settings del repo público `horangelmillan/email-ia` (plan Free permite branch protection solo en público; ya activo en `main` `PROJECT_STATE.md:77`). No requiere cambio de archivo; verificado en Fase 3A.
- **CodeQL** (`.github/workflows/codeql.yml`): `javascript-typescript` con `queries: security-and-quality`, triggers `push/PR` en `main/develop` + `schedule` semanal lunes 06:00 UTC. `permissions: security-events:write` solo en job `analyze`. `timeout 15 min`, `autobuild`. Coste en plan Free ~3-5 min por run, dentro de cuota; se monitorea y se puede limitar a `schedule` si excede. No añade infra local ni rompe `vite@6`/`electron-builder` npx.
- **Branch protection** (`main`/`develop`): `PR obligatorio + check quality + enforce admins + sin force push` ya activo (`PROJECT_STATE.md:77`). `required_approving_review_count=0` se mantiene en repo solitario; subir a ≥1 cuando haya colaboradores.

## Alternativas evaluadas

| Opción                                                    | Resultado                                                                                                |
| --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| Mantener `ci.yml` mínimo sin `format:check`/`concurrency` | Descartada: `format:check` es gate de `LF` y `concurrency` ahorra minutos Actions                        |
| Añadir job separado `format`/`lint` paralelo              | Descartada YAGNI: job único `quality` ~3 min, paralelizar añade matriz sin beneficio en monorepo pequeño |
| CodeQL con `security-only`                                | Descartada: `security-and-quality` aporta valor sin coste extra significativo                            |
| CodeQL solo `schedule` sin `push/PR`                      | Descartada: pierde feedback en PR; se mantiene PR + schedule                                             |
| Trivy/Snyk además de CodeQL                               | Descartado: `npm audit` + `gitleaks` + CodeQL cubren superficie sin duplicar scanners                    |

## Consecuencias

**Positivas**

- Gate completo `lint/typecheck/build/test:coverage/format:check/gitleaks` en cada PR a `main/develop` con cancelación de runs obsoletos.
- Secret scanning + CodeQL activos en repo público sin infra adicional; privacy-first preservado (sin SaaS con envío a terceros).
- `develop` 10 commits delante de `main` sincronizable vía PR `develop→main` tras merge de `feature/fase2-ui-electron` (Fase 3A).

**Negativas / pendientes**

- CodeQL añade ~3 min por PR; monitorear cuota Actions Free y ajustar a `schedule` si es necesario.
- `electron-builder` sigue vía `npx` (hang pnpm Windows `ADR-006:42`); en CI Linux puede reinstalarse sin hang cuando pnpm 11 resuelva.
- Observabilidad OTel+Pino y contratos Pact quedan para Fase 3B/4 (fuera de alcance 3A).
