# ADR-001: Fundación del monorepo (pnpm + estructura custom)

- **Estado**: Aceptado
- **Fecha**: 2026-08-19
- **Reemplaza a**: Ninguno
- **Referencias**: ARCHITECTURE_DECISIONS.md §7, PROJECT.md

## Contexto

El proyecto es una aplicación Desktop First (Electron) con backend Node/Express reutilizable para una futura versión Web. Se necesitaba decidir el gestor de paquetes, la estructura de repositorio, la versión de Node.js y la configuración base de TypeScript/editor antes de iniciar cualquier scaffolding.

## Decisión

- **Package manager**: pnpm (workspaces).
- **Estructura**: monorepo custom con `pnpm-workspace.yaml`, sin Nx ni Turborepo inicialmente.
- **Node.js**: última versión LTS estable al momento del scaffolding (fijar en `.nvmrc`/`engines` en Fase 1).
- **TypeScript**: mejores prácticas con ES modules, configuración base compartida (`tools/tsconfig`) y aliases `@` para rutas.
- **EditorConfig**: configurado con mejores prácticas para OpenCode, VSCode y GitHub.

## Alternativas evaluadas

| Opción                 | Resultado                                                           |
| ---------------------- | ------------------------------------------------------------------- |
| pnpm + monorepo custom | **Elegida**: control total, disk-efficient, sin overhead de tooling |
| Nx                     | Descartada: generators/plugins opinionados, curva de aprendizaje    |
| Turborepo              | Descartada: menos flexible, dependencia de Vercel                   |
| npm workspaces         | Descartada: más lento, peer deps problemáticas                      |
| Polyrepo               | Descartada: complejidad de compartir código entre frontend/backend  |

## Consecuencias

**Positivas**

- Workspaces pnpm con enlaces eficientes entre paquetes (core, backend, frontend, electron, ai-provider, db, shared).
- Estructura de carpetas diseñada para el proyecto, alineada con la arquitectura hexagonal definida.
- Menor acoplamiento a herramientas externas.

**Negativas / pendientes**

- El tooling propio (scripts de build/test) debe configurarse manualmente.
- Nx/Turborepo podrán reevaluarse si el crecimiento del proyecto lo justifica (caché distribuida, pipelines avanzados).
