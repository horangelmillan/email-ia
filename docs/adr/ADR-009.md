# ADR-009: Observabilidad Fase 3B — Pino + OTel SDK opcional + health checks

- **Estado**: Aceptado
- **Fecha**: 2026-08-27
- **Reemplaza a**: Ninguno (concreta ARCHITECTURE_DECISIONS §3.5 y §8 D10, ADR-002 §Observabilidad, PROJECT_STATE Fase 3B)
- **Referencias**: ARCHITECTURE_DECISIONS §3.5, ADR-002, ADR-008, PROJECT_STATE Fase 3B, `packages/shared/src/config/env.ts`, `packages/backend/src/observability/*`, `packages/backend/src/app.ts`, `packages/backend/src/health/*`

## Contexto

Fase 3A cerró CI/CD (`ADR-007`, baseline 72 tests 91%/81.3% verde). `PROJECT_STATE.md:143` define Fase 3B como observabilidad: logging estructurado Pino, configuración `dotenv+zod`, OTel SDK con export OTLP opcional deshabilitado por defecto (privacy-first, `ADR-002:50`), y health/readiness en Express local. `ARCHITECTURE_DECISIONS §3.5` exige esas capacidades antes de Fase 4 (contratos integraciones). Sin OTel activable y sin health checks, el backend no es operable ni testeable (Pact/Playwright futuros requieren `/health`).

## Decisión

- **Config** (`packages/shared`): `envSchema` (`zod@4.4.3`) centraliza `NODE_ENV`/`PORT`/`LOG_LEVEL`/`OTEL_ENABLED`/`OTEL_SERVICE_NAME`/`OTEL_EXPORTER_OTLP_ENDPOINT`/`DATABASE_URL|ENCRYPTION_KEY` con coerción `string→number/boolean`, defaults `LOG_LEVEL info`, `OTEL_ENABLED false` (privacy-first), `endpoint http://localhost:4318`. Helpers `parseEnv(raw)` (testable sin env) + `loadEnv()` (`dotenv.config()` + parse). Exportados desde `@email-ia/shared`. DI: ningún paquete lee `process.env` directo en lógica de dominio; backend/electron inyectan `Env`.

- **Logger** (`packages/backend/src/observability/logger.ts`): `createLogger({level, enabled?}, destination?)` factoría `pino@latest` (`name: email-ia`, `level` del env). `enabled:false → silent`. `DestinationStream` inyectable permite tests con `Writable` sin I/O real (cobertura 100%). Sin `pino-pretty` transport en producción (evita worker thread); pretty solo en dev vía config `pretty` futura YAGNI.

- **OTel** (`packages/backend/src/observability/otel.ts`): `createOtelSdk({enabled, serviceName, endpoint}, deps?)` — `enabled false → null` (no SDK, no export, coste 0). Si `enabled true`, crea `NodeSDK` (`@opentelemetry/sdk-node`) + `OTLPTraceExporter` (`@opentelemetry/exporter-trace-otlp-http`, `url ${endpoint}/v1/traces`) + `resourceFromAttributes({ service.name })` (`@opentelemetry/resources` + `semantic-conventions`). `deps` inyecta `NodeSdkCtor`/`exporterFactory` para tests sin red. `protobufjs` en `allowBuilds:false` (no build nativo; export deshabilitado por defecto). Exporta `OtelSdk {start, shutdown}`; lifecycle gestionado por backend `server.ts` futuro (no acoplar Core).

- **Health** (`packages/backend/src/health/health.ts`): `getHealth(): {status ok, timestamp ISO, uptime}` y `getReadiness(checks): {status ok|error, timestamp, checks}` (error si algún check `error`). Lógica pura sin I/O, 100% cobertura.

- **Express** (`packages/backend/src/app.ts`): `createApp({logger?, readinessChecks?, setup?}): Express` con `helmet`+`cors`+`compression`+`express.json()` (seguridad `ENGINEERING.md:59`), `pino-http` opcional (solo si logger, DI), rutas `GET /health` (200 `getHealth()`) y `GET /ready` (200/503 según `getReadiness(await readinessChecks())`), `setup` hook para inyectar rutas antes del error handler (testeabilidad), error handler unificado `AppError → status/code/message/details` else `500 INTERNAL_ERROR` (`core/src/errors/app-error.ts:6`). `allowBuilds: {protobufjs:false}` evita `ERR_PNPM_IGNORED_BUILDS`.

- **Hexagonal**: `shared` (config) ← `backend` (observabilidad+health+app). `core` no depende de `pino`/`otel`/`express`; dependency rule `shared←core←db|ai-provider←backend←electron` preservada (`ADR-001/002/003`, `hexagonal-email-ia:12`).

## Alternativas evaluadas

| Opción                                                                   | Resultado                                                                                           |
| ------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------- |
| `winston` vs `pino`                                                      | Descartada: `pino` ya decidido `ADR-002:17`, más rápido, JSON nativo                                |
| OTel auto-instrumentations (`@opentelemetry/auto-instrumentations-node`) | Descartada YAGNI: añade overhead y deps; se añade solo si métricas lo requieren Fase 4+             |
| Export OTLP `proto` vs `http`                                            | **Elegida `http`**: JSON sin `protobufjs` build; `proto` descartada por toolchain nativa Windows    |
| Config en `backend` vs `shared`                                          | **Elegida `shared`**: isomórfica, reutilizable por `electron`/`frontend` futuros sin duplicar `zod` |
| Health en `core` port                                                    | Descartada: health es infra del backend, no dominio; YAGNI port en `core`                           |

## Consecuencias

**Positivas**

- Privacy-first: OTel off por defecto, sin envío a terceros sin `OTEL_ENABLED=true` (`ADR-002:50`).
- Operabilidad: `/health`/`/ready` listos para CI, Pact, Playwright y `electron` IPC healthCheck futuro.
- TDD ≥80%: 103 tests ( +31 Fase 3B), 91.62% statements / 82.15% branches, `lint/format:check/typecheck/build` verdes; `pino-http` ESM fix via `import * as` para `NodeNext`.
- Config testeable: `parseEnv` sin `process.env`, `loadEnv` con `dotenv`.

**Negativas / pendientes**

- `pino-pretty` no integrado (YAGNI hasta dev DX); `OTEL_ENABLED` requiere `OTEL_EXPORTER_OTLP_ENDPOINT` accesible (collector no desplegado — pendiente Loki/Tempo `ARCH §3.5` Fase 4+).
- `server.ts` con `app.listen` y `OtelSdk.start/shutdown` queda para Fase 4 (backend aún sin `start` real; `createApp` es factoría pura).
- `protobufjs` deshabilitado; si se activa OTLP en CI Linux, evaluar `allowBuilds: true` para exporter `proto`.
