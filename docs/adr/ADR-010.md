# ADR-010: Prompt framework versionado + golden dataset (Fase 5B)

- **Estado**: Aceptado
- **Fecha**: 2026-08-28
- **Reemplaza a**: Ninguno (concreta ARCHITECTURE_DECISIONS §3.7 Prompt engineering, ADR-002 §IA)
- **Referencias**: ARCHITECTURE_DECISIONS §3.7, §3.8, ADR-002, ADR-003, ADR-009, PROJECT_STATE Fase 5B, `packages/core/src/ports/prompt.port.ts`, `packages/backend/src/prompts/prompt.service.ts`

## Contexto

Fase 5A cerró RAG (`RagPort`+`VectorStorePort`+`DrizzleVectorStore`+`RagService`, PR #25 `6172fbe`, 186 tests 91%/84% verde). `ARCHITECTURE_DECISIONS §3.7` exige sistema propio de prompts: plantillas versionadas independientes del código, variables tipadas, versiones, metadatos, selección por modelo y evaluación con golden dataset para evitar regresiones antes de adoptar cambios. Sin ello, los prompts quedan hardcodeados en `RagService`/`AIProviderPort.chat` y no hay forma de versionar, validar variables ni medir calidad.

Requisitos: `shared←core←backend` intacta (hexagonal), Node 22 pnpm 11, `strict exactOptionalPropertyTypes`, coverage ≥80%, `format:check` LF, `allowBuilds` sin cambios, `OTel`/`Pino` opcionales.

## Decisión

- **Puerto en Core** (`packages/core/src/ports/prompt.port.ts`): `PromptVariable` (`name`, `type: 'string'|'number'|'boolean'`, `required?`, `description?`), `PromptMetadata` (`description?`, `tags?`, `author?`, `createdAt?`), `PromptMessageTemplate` (`role: ChatRole`, `content` con `{{var}}`), `PromptTemplate` (`name`, `version` semver, `description?`, `metadata?`, `modelSelector?: string[]`, `variables[]`, `messages[]`), `GoldenCase` (`id`, `promptName`, `version?`, `variables`, `expected?`/`expectedContains?`), `EvaluationResult` (`total`/`passed`/`failed` + `cases[]`). `PromptPort` (`get(name, version?)→PromptTemplate|null`, `list()`, `render(name, variables, version?)→ChatMessage[]`, `evaluate(cases)→EvaluationResult`). Tipos puros, `exactOptionalPropertyTypes` (`type?: T|undefined`).

- **Error unificado** (`packages/core/src/errors/prompt-error.ts`): `PromptError extends AppError` (`code PROMPT_ERROR`, `status 400`). Exportado desde `@email-ia/core`.

- **Backend** (`packages/backend/src/prompts/prompt.service.ts`): `PromptService implements PromptPort` DI `(templates: PromptTemplate[], ai: AIProviderPort|null)`. Agrupa por `name`, ordena por `compareVersions` semver numérico, `get` devuelve latest si `version` omitida. `interpolate` con `replaceAll(/\{\{\s*(\w+)\s*\}\}/g, variables[key] ?? '')`. `validateVariables` tipada (required + `typeof` por `type`) → `PromptError`. `render` → `ChatMessage[]` vía `interpolate`. `evaluate` itera `GoldenCase`, `render` + `ai.chat`, compara `expected` exacto o `expectedContains` case-insensitive, acumula `passed/failed`; sin `ai` → `PromptError`; `cases.length===0` → `0/0`. Helpers puros, sin regex polinomial (`stripTrailingSlash`-style innecesario, patrón fijo).

- **Recursos independientes** (`packages/backend/src/prompts/*.json`): `summarize-email.v1.0.0.json` (variables `subject?`/`body!`, system+user), `summarize-email.v1.1.0.json` (añade `tone?`, `modelSelector ["llama-3","gpt-4"]`), `classify-email.v1.0.0.json` (variables `subject!`/`priority? number`), `golden-dataset.json` (3 casos: `summarize-001/002` `expectedContains` reunión/Descuento, `classify-001` trabajo). JSON cargables vía `resolveJsonModule:true` sin código, versionables, metadatos incluidos.

- **Hexagonal**: `core` no depende de `backend`/`ai-provider`; `backend` depende de `@email-ia/core` y adapta `PromptPort`. Orden `shared←core←backend` preservado (`ADR-001/002/003`, `hexagonal-email-ia:12`). Sin nueva dep (stdlib antes que dep, ponytail).

- **Testing**: `packages/core/src/errors/prompt-error.test.ts` (2 tests `PROMPT_ERROR`), `packages/backend/src/prompts/prompt.service.test.ts` (13 tests: get latest/específico/null, list, render interpolate, required/type mismatch, not found, evaluate contains/exact/no ai/empty, semver ordering 1.1.0>1.0.10). 202 tests 91.82%/83.94% verde.

- **Config**: `vitest.config.ts:23` añade `**/*.json` a `exclude` coverage para no penalizar recursos (pact JSON ya multilínea).

## Alternativas evaluadas

| Opción                                         | Resultado                                                                                                                                            |
| ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| Plantillas en código TS hardcodeadas           | Descartada: acopla prompts a build, impide versionar sin redeploy (§3.7 exige recursos independientes)                                               |
| Zod schemas por prompt para `variables`        | Descartada YAGNI Fase 5B: `PromptVariable.type` + `typeof` runtime suficiente; zod queda disponible si crece complejidad                             |
| Almacén DB para prompts (`email_chunks` style) | Descartada YAGNI: filesystem JSON versionado git cubre trazabilidad + `drizzle` ya usado para RAG; evolución a DB no rompe puerto                    |
| Evaluación con scoring LLM-as-judge complejo   | Descartada: `expected` exacto / `expectedContains` substring es determinista, testeable sin red, suficiente para golden dataset inicial (§3.7 evals) |
| `{{var}}` con handlebars/mustache dep          | Descartada: stdlib `replaceAll` regex fijo cubre YAGNI, evita dep + CodeQL polynomial regex (§3.7 ponytail)                                          |

## Consecuencias

**Positivas**

- Prompts versionados trazables en git, validados tipadamente, seleccionables por modelo (`modelSelector`), render puro testeable sin red (`DI AIProviderPort` mockeado).
- Golden dataset (`golden-dataset.json`) permite validar cambios antes de adoptar versión (evaluación determinista pass/fail), evitando regresiones.
- Puertos en `core` desacoplan dominio de implementación; `PromptService` reutilizable para Fase 5C UI5/Electron (misma API).

**Negativas / pendientes**

- `evaluate` actual usa substring/exacto; métricas semánticas (cosine, BLEU) quedan para evolución cuando haya volumen.
- `golden-dataset.json` inicial 3 casos mínimo; ampliar dataset en Fase 5C con casos reales anonimizados (privacy-first, offline-first).
- `compareVersions` semver simple (numeric split); no soporta prerelease/build metadata (YAGNI Fase 5B).
