# ADR-008: Harness Engineering — optimización MCP + Skills con sinergia

- **Estado**: Aceptado
- **Fecha**: 2026-08-27
- **Reemplaza a**: Ninguno (concreta `ARCHITECTURE_DECISIONS.md:3` y `AGENTS.md:1` harness)
- **Referencias**: `ARCHITECTURE_DECISIONS.md:3`, `AGENTS.md:1`, `PROJECT_STATE.md:7`, `docs/harness.md:1`, `~/.config/opencode/opencode.jsonc:3`, `~/.config/opencode/AGENTS.md:14`

## Contexto

`AGENTS.md` (27 líneas) y `~/.config/opencode/AGENTS.md` declaraban 4 MCP y 7 skills pero solo 1 existía en disco (`playwright-testing` de `odata-server`, no Email IA). Sin matriz sinérgica, el agente elegía MCP/skill ad-hoc, sin TDD estricto, sin validación hexagonal, sin guía UI5 Email IA. `ARCHITECTURE_DECISIONS.md:3` exige calidad automatizada, testing (Vitest/Playwright/Pact), CI/CD, observabilidad OTel, Drizzle, Electron, UI5 CLI v4 — sin harness no es enforceable.

Investigación en `https://www.skills.sh/` (leaderboard + topic `testing`/`agent-workflows` + probes `api/v1/skills/search` 401 sin Vercel OIDC) reveló ~200 skills relevantes en packs `bobmatnyc/claude-mpm-skills` (172), `obra/superpowers` (14), `antfu/skills` (19), `ccheney/robust-skills`, `davila7/claude-code-templates` (852). `dietrichgebert/ponytail` (45K installs, 112K stars, audits pass) faltaba en `~/.config/opencode/skills`.

## Decisión

**Pack completo + 2 skills locales + 1 MCP + AGENTS.md sinérgico.**

1. **MCP**: añadir `eslint` (`npx @eslint/mcp@latest`, local) a `opencode.jsonc:22` junto a `codebase-memory`, `context7`, `github`, `playwright`. `opentelemetry` queda sin MCP hasta Fase 3B.

2. **Skills globales** (`~/.config/opencode/skills/` via `~/.agents/skills` copy — `skills` CLI instala en `~/.agents/skills`):
   `ponytail` (copiado manual por `PromptScript does not support global skill installation`), `vitest`, `sapui5`, `context7-mcp`, `antfu`, `typescript-core`, `drizzle`, `drizzle-migrations`, `clean-ddd-hexagonal`, `clean-code`, `git-workflow`, `github-actions`, `opentelemetry`, `api-documentation`, `playwright`, `playwright-best-practices`, `playwright-cli`, `webapp-testing`, `test-driven-development`, `verification-before-completion`, `systematic-debugging`, `writing-plans`, `executing-plans`, `brainstorming`, `dispatching-parallel-agents`, `subagent-driven-development`, `finishing-a-development-branch`, `requesting-code-review`, `using-git-worktrees`, `playwright-testing` (+ vercel skills). Total ~41 globales, ~42 en opencode tras sync.

3. **Skills locales** (`.opencode/skills/`):
   - `sapui5-email-ia` — UI5 CLI v4 4.0 + OpenUI5 1.133.0, `Component.js`/`manifest.json` routing `home/inbox`, `model/models.js`, `service/EmailService.js`, `i18n_en/es` (gap 0 hits en skills.sh para SAPUI5).
   - `hexagonal-email-ia` — dependency rule `shared←core←db|ai-provider←backend←electron`, ports `AIProviderPort`/`SecretStorePort`/`ModelManagerPort` + `AppError`/`ProviderError`/`DbError`, DI obligatorio, `preload.cjs` para `sandbox:true`.

4. **`AGENTS.md` refactorizado** (27→~95 líneas): sección 1 lectura obligatoria orden estricto, sección 2 matriz 14 filas (fase workflow → MCP → skills → cuándo), 7 reglas de sinergia estrictas, sección 5 harness vivo (`docs/harness.md`, `ADR-008`), sección 6 resumen skills/MCP. Mantiene `Desarrollo → Planificar → Implementar → lint/tests → actualizar estado → commit` (`DEVELOPMENT_WORKFLOW.md:5`).

5. **`docs/harness.md`** catálogo vivo: tablas MCP + skills globales/locales con repo/versión/fase, sinergia, instalación/mantenimiento, historial.

6. **Global `~/.config/opencode/AGENTS.md`**: sinérgico pero este `AGENTS.md` proyecto prevalece (`Proyecto > Global > Modelo`).

## Alternativas evaluadas

| Opción                                              | Resultado                                                                                                                   |
| --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Minimalista (solo reparar 6 huérfanas + 3 críticas) | Descartada: dejaba sin TDD, sin Playwright hardening, sin Drizzle migrations, sin OTel Fase 3B — insuficiente para `ARCH:3` |
| Solo global, sin locales                            | Descartada: `sapui5-email-ia`/`hexagonal-email-ia` son específicas Email IA, no reutilizables globalmente                   |
| No añadir `eslint` MCP                              | Descartada: `eslint.config.js` flat requiere autofix asistido; coste cero, aprobado por usuario                             |
| `biome` en vez de `eslint+prettier`                 | Descartada: ADR-002 decide `eslint+prettier` separados; `biome` no aporta valor aquí                                        |
| `Nx/Turborepo`                                      | Descartado ADR-001: pnpm custom suficiente, reevaluar solo con crecimiento                                                  |
| `skills.sh` automático sin curado                   | Descartado: `api/v1` 401, leaderboard genérico; se hizo barrido manual + validación valor/coste                             |

## Consecuencias

**Positivas**

- Cada fase `DEVELOPMENT_WORKFLOW.md` tiene MCP/skill asignado — el agente no improvisa. TDD, hexagonal, UI5 Email IA, Drizzle, OTel, Playwright con gates.
- `ponytail full` por defecto reduce over-engineering (YAGNI, stdlib primero).
- `playwright-testing` legacy ahora complementado por `sapui5-email-ia` específica Email IA.
- `npx skills list -g` verificable, `docs/harness.md` trazable, `AGENTS.md` enforceable por sesión.

**Negativas / pendientes**

- Copia manual `.agents→.config/opencode` necesaria por `PromptScript does not support global skill installation` — automatizable con script `experimental_sync`.
- `playwright-testing/SKILL.md` con YAML `:` sin comillas provoca `YAML parse error` en `skills list -g` — corregir quoting si se mantiene.
- `drizzle` nombre real es `drizzle` (no `drizzle-orm`) en `bobmatnyc/claude-mpm-skills` — alias corregido.
- Cuota `skills.sh` prefiere `~/.agents/skills`; duplicar a `~/.config/opencode/skills` duplica disco (~41 carpetas) — aceptable (<50 MB).
- `codebase-memory` SKILL.md con YAML inválido (mismo error `:` ) — corregir upstream.

## Validación

`pnpm lint` + `pnpm format:check` + `pnpm typecheck` + `pnpm build` + `pnpm test:coverage` (≥80%) verdes tras cambios solo docs/skills (sin tocar `packages/*`). `npx skills list -g` muestra 41 globales.
