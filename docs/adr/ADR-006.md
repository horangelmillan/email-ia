# ADR-006: Bootstrap UI5 CLI v4 + vite-plugin-electron + electron-builder + IPC tipado

- **Estado**: Aceptado
- **Fecha**: 2026-08-22
- **Reemplaza a**: Ninguno (concreta ADR-002 §Frontend/Desktop y PROJECT_STATE Fase 2 Tarea 4)
- **Referencias**: ARCHITECTURE_DECISIONS §3.6 y §8 D7-D8, ADR-001, ADR-002, PROJECT_STATE Fase 2, spike 2026-08-19

## Contexto

Fase 2 Tarea 4 exigía materializar el frontend y el contenedor Desktop sin romper la arquitectura hexagonal (Electron solo contenedor, Core reutilizable para Web). El scaffolding `packages/frontend` era placeholder (`echo`, `ADRs 001/002`) y `packages/electron` solo tenía el spike `src/main.ts` + `preload.cjs` con `sandbox:true`. Faltaba: UI5 CLI v4 (routing/models/services, sucesor oficial de UI5 Tooling), HMR para Electron y empaquetado con copia de preload, e IPC tipado `renderer ↔ main`. Además recayó el desfase CRLF (`core.autocrlf=true` → 46 files con `format:check` en rojo) y `electron-builder@25.1.8` provoca hang infinito de `pnpm --filter`/`pnpm -r` en Windows.

## Decisión

- **Frontend** `packages/frontend`: `@ui5/cli@4.0.14` (devDep). `ui5.yaml` `specVersion: '4.0'`, `framework: OpenUI5 1.133.0` (`sap.m`, `sap.ui.core`, `sap.f`, `sap.ui.layout`, `themelib_sap_horizon`). `webapp/` con `Component.js` (`sap/ui/core/UIComponent`, `models.createAppModel/createDeviceModel`, `getRouter().initialize()`), `manifest.json` (i18n `com.emailia.frontend.i18n.i18n`, modelos `i18n`/`app`, routing `home:''` → `Home` y `inbox:'inbox'` → `Inbox`, `minUI5Version 1.133.0`), `index.html` (bootstrap `https://sdk.openui5.org/1.133.0/resources/sap-ui-core.js`, `theme sap_horizon`, `resourceroots com.emailia.frontend`), `controller/App`/`Home`/`Inbox`, `view/App`/`Home`/`Inbox`, `model/models.js` (JSONModel Device OneWay), `service/EmailService.js` (placeholder `getInboxSummary`/`healthCheck`), `i18n/i18n.properties` + `i18n_en/es.properties` (evita warning `fallbackLocale`), `css/style.css`. Scripts: `build: ui5 build --all --clean-dest --dest dist`, `start: ui5 serve --port 8080`, `typecheck` placeholder. Build OK (7 proyectos, `ProjectBuilder Build succeeded`).

- **Electron** `packages/electron`: `vite@6.3.5` + `vite-plugin-electron@0.28.8` + `vite-plugin-electron-renderer@1.0.0` (devDeps). `vite.config.ts` (`defineConfig` + `electron({main:{entry:'src/main.ts', vite:{build:{outDir:'dist'}}}, preload:{input:'src/preload.ts', vite:{build:{outDir:'dist'}}}})`) — sin `onstart` en build para no lanzar Electron. `src/preload.ts` (TS, `contextBridge.exposeInMainWorld` con `ping`/`getVersions` tipados) y `preload.cjs` legacy actualizado con `ipcRenderer.invoke`. `src/ipc.ts` (`registerIpcHandlers` con `ipcMain.handle('ping'/'get-versions')`, DI de `@email-ia/core`). `src/main.ts` con `existsSync` fallback (`dist/preload.mjs` vs `../preload.cjs`) y `dist/index.html` vs `../index.html`, `registerIpcHandlers()` en `app.whenReady`, `sandbox:true`/`contextIsolation:true`. `electron-builder.yml` (`appId com.emailia.app`, `files: dist/**/*, preload.cjs, index.html`, `extraResources`). `pnpm --filter @electron dev/build:vite` OK (`vite build` 3 envs). `electron-builder` retirado de `devDependencies` por hang pnpm (ver Consecuencias); empaquetado vía `npx --yes electron-builder` (`scripts.package`).

- **Calidad**: `eslint.config.js` ignora `**/dist-electron/**` + `**/release/**`, `.prettierignore` ignora `dist-electron/release`, `.gitattributes` + `git config core.autocrlf false` + `git add --renormalize .` + `pnpm format` corrigen CRLF. `pnpm build/typecheck/lint/test:coverage` verdes (72 tests, 91.05 %/81.34 %).

- **Hexagonal**: `packages/core` sin dependencia de `electron`/`frontend`; `packages/electron` y `frontend` dependen de `@email-ia/core`/`shared` solo vía protocolos. Orden: `core → db/ai-provider → backend/electron/frontend`.

## Alternativas evaluadas

| Opción                                                    | Resultado                                                                                                                  |
| --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `@ui5/cli` V4 + OpenUI5 CDN (`sdk.openui5.org`)           | **Elegida**: oficial, estable, ESM, sin webpack; Vite middleware comunitario descartado                                    |
| UI5 Tooling Vite comunitario / Custom Vite + @ui5/builder | Descartadas: beta/no oficial, mantenimiento extra                                                                          |
| `vite-plugin-electron` (simple) + `electron-builder`      | **Elegida**: HMR nativo Vite, build simple; `electron-forge` descartado (webpack legacy, config compleja)                  |
| `electron-builder` instalado en workspace                 | Descartada temporalmente: hang pnpm en Windows (ver Hallazgos); se usa vía `npx`                                           |
| `preload` ESM en sandbox                                  | Descartada: `sandbox:true` exige CJS; se mantiene `preload.cjs` legacy + `preload.ts` (build a `preload.mjs` con fallback) |

## Consecuencias

Positivas:

- UI5 CLI v4 bootstrap completo y verificable (`ui5 build`/`serve`) sin acoplar Core a Electron; routing/models/services siguen MVC del repo referencia SmartInventory-frontend.
- Electron HMR + IPC tipado sin romper hexagonal; preload copia a `dist` y fallback CRLF resuelto.
- Baseline verde recuperado (`pnpm build 38 s frontend + tsc`, `typecheck`, `lint`, `test:coverage` OK, `format:check` OK).

Negativas / pendientes:

- `electron-builder` fuera de `package.json` hasta que pnpm/Windows resuelva hang (monitorear `pnpm` 11 + `electron-builder` 26); en CI Linux puede reinstalarse sin hang.
- `vite build` genera `dist/preload.mjs` minificado con `require` (no afecta lint por ignores); `pnpm -r` no ejecuta `vite build` en CI — se mantiene `tsc` como `build` principal.
- RAG/vector store, OTel, Pact, Playwright e2e quedan para Fase 3/4.
